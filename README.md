## 📖 关于 Szy_Pay

**Szy_Pay** 是一套面向数字商业的**电子支付通道平台**：对上聚合各家支付渠道，对下给商户一套统一的收款接口、收银台与自助中心，把订单、回调、结算、对账、风控这些繁杂环节收敛成开箱即用的服务。

它覆盖了一个**易支付 / 聚合支付系统**该有的完整链路，并在此之上把**商户进件（服务商模式）**做成了主线能力 —— 每个商户在平台服务商名下进件、拿到自己的子商户号，资金由上游**直清到商户自己的账户**，平台不碰本金、不做资金归集。

**适合谁**

- 想搭建自有**支付网关 / 聚合收款平台**的团队；
- 需要**服务商模式商户进件**（微信特约商户 `sub_mchid`、直连通道子商户号）的服务商；
- 想研究现代化支付系统工程实现（Go 后端 + Vue 3 前端）的开发者。

## 🌟 近期特色功能

### 🏦 服务商商户进件（不走二清）

平台以**服务商模式**接入渠道，为每个商户单独进件、单独持号，从根上规避资金归集风险。

- **半自动 + 全自动两档进件**：支持后台代录资料，也支持对接渠道进件接口（如微信 `applyment4sub`）全自动提单；
- **一户一号**：进件成功回填商户自己的子商户号（微信 `sub_mchid`、直连渠道各自号段），下单 / 退款 / 结算 / 分账全链路统一使用商户号；
- **资金直清**：收款直接结算到商户自己的账户主体，平台账户无资金停留；
- **进度可视**：进件状态贴合渠道真实阶段（资料审核 → 待账户验证 → 待签约 → 已开通），不含糊其辞；
- **敏感信息合规**：进件资料敏感字段加密落库、回显脱敏。

> 硬约束：未进件成功的商户，该通道对他不可用、下单直接拒绝，**不回退平台商户号**。

### 🛡️ 进件风控与业务受限管控

进件不是提交完就结束，商户开通后的**业务受限状态**同样需要被持续盯住。

- **驳回原因结构化**：渠道驳回逐字段回显（字段名 + 驳回理由），商户端和运营后台都能看懂该改哪一项，改完原地重提；
- **业务受限查询与快照**：定时拉取子商户的受限状态（收款 / 退款 / 提现 / 分账等维度）并留存快照，运营后台总览 + 明细抽屉一眼看全；
- **受限即锁**：一旦查到受限，收单、退款、提现、分账等关键动作立即在业务侧硬锁，避免明知会失败还去打渠道接口；
- **处置通知实时订阅**：接入渠道的**违规处置通知**与**合作伙伴管控订阅**回调，验签解密后落追加型流水，处置时间线可回溯；
- **解脱代办**：受限后需要补正的常见场景（变更结算账户、变更主体资料）提供自助入口，商户自己就能发起。

### 📣 微信消费者投诉 2.0 全闭环

把投诉从「渠道后台单独处理」搬进平台，运营和商户在同一套系统里闭环。

- **投诉工单台**：统计概览 + 状态分类 + 详情抽屉，协商历史按时间线展开；
- **完整处置动作**：回复投诉人、上传凭证图片、发起退款审批、即时服务响应；
- **消息驱动 + 定时兜底**：投诉通知回调实时入库（顶层 ID 幂等），另有定时对账刷新快照，不漏单；
- **商户端自助视图**：商户可查看并处理自己名下的投诉，越权访问在服务端拦截；
- **站内信触达**：新投诉与状态变化即时推送到商户站内信，不靠人工盯。

## 🌱 我们的故事

Szy_Pay 始于一个朴素的观察：**收款本不该这么难。**

对很多团队来说，把在线收款跑通，意味着要在纷繁的渠道、术语、进件材料和对账规则里反复摸索，把大量精力耗在与核心业务无关的地方。我们想改变这一点。

于是我们从零开始，用现代化的工程方法构建了这套支付通道平台 —— 认真思考「一笔钱应该怎样安全、清晰地从付款人走到商户账户」这个最本质的问题。我们在稳定性、资金安全和使用体验上反复打磨，宁可慢一点，也要把每一个环节做扎实。尤其在**合规**上不走捷径：坚持一户一号、资金直清，把「不碰本金」写进架构而不是写进承诺。

Szy_Pay 是这份坚持的结果，也是一个仍在持续生长的平台。我们把 **「让每一笔收款，都简单可靠」** 作为信条，一步一步把它做得更好。

> 💡 **一点致意** —— 谨向所有在支付领域默默铺路的开源项目与开发者致敬。正是这些前行者点亮了我们的思路，激励我们以自己的方式，去探索一条更现代的支付之路。

## 🧱 技术构成

Szy_Pay 采用前后端分离架构，以现代化的技术栈构建：

| 层次 | 技术 | 说明 |
|---|---|---|
| **后端** | Go | 高并发、内存安全，胜任支付场景对稳定与性能的要求。 |
| **前端** | Vue 3 + TypeScript | 组件化、类型安全，构建清爽流畅的管理与自助界面。 |
| **构建** | Vite + Tailwind CSS | 现代化前端工程与一致的视觉体系。 |
| **数据** | MySQL（utf8mb4） | 金额一律走精确十进制，杜绝浮点误差。 |
| **安全** | RSA / SHA256 / AES-GCM | 渠道报文签名验签、回调解密、敏感字段加密落库。 |

**三端结构**

- **运营后台** —— 平台方的管理控制台：通道、商户、订单、结算、风控、进件、投诉；
- **商户中心** —— 商户自助端：接入配置、进件、账单、提现、退款、受限自查；
- **官网 / 收银台** —— 品牌门面、开发文档与面向付款人的支付页。
